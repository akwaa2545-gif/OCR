# Current employee file migration

Unreferenced physical versions require a separate reviewed ownership JSON supplied to `inventory --retained-ownership <json>`. Its shape is `[{"EmployeeCode":"00123","Kind":"Certificate","RelativeKey":"00123/old.pdf"}]`. Store this input inside the private work root established by the first inventory; input/file/directory permissions and ownership are checked before JSON parsing. This records an immutable retained version with no skill row, owner pointer or alias. Current status is still required, and conflicting/duplicate mappings are excluded. The map never overrides a database-referenced or ambiguous attachment. Unknown ownership remains a report item.

This .NET 8 console never removes or rewrites source files. Database credentials come only from the private `OCR_FILE_MIGRATION_CONNECTION` environment variable (or a variable named by `--connection-env`). Do not place credentials in commands, manifests, checkpoints or source control.

Offline tests: `dotnet test tests/OperatorCertificationRecord.FileMigration.Tests --filter 'Category!=SqlIntegration'`. The full suite additionally requires a private `OCR_FILE_STORAGE_TEST_CONNECTION` environment variable and accepts only local `OcrFileStorageTests_` databases. Its SQL integration fixture generates its own leading-zero employee codes, source files and stable qualification IDs; it executes the public CLI inventory, verification, dry-run and bounded apply/retry commands, verifies hashes and journal counts, stale owner rollback, SQL authority, retained unlinked versions, null employee ownership and resignation races, then cleans only its own rows. The executed fixture uses SQL Server 2022 at compatibility level 120; actual SQL Server 2014 validation remains a deployment check.

Run against an isolated fixture first. Production execution requires the separately recorded schema/preparation and reader/writer deployment gates. Every supported desktop and web writer must support SQL authority before `--clients-sql-aware` is truthful.

```powershell
dotnet run --project OperatorCertificationRecord.FileMigration -- inventory --roots 'D:\fixture\share;D:\fixture\mirror' --work-root 'D:\private-ocr-migration' --manifest 'D:\private-ocr-migration\inventory-001.json'
dotnet run --project OperatorCertificationRecord.FileMigration -- verify-manifest --work-root 'D:\private-ocr-migration' --manifest 'D:\private-ocr-migration\inventory-001.json' --employee-kind Photo --employees 00123
dotnet run --project OperatorCertificationRecord.FileMigration -- import --dry-run --work-root 'D:\private-ocr-migration' --manifest 'D:\private-ocr-migration\inventory-001.json' --employee-kind Photo --employees 00123
dotnet run --project OperatorCertificationRecord.FileMigration -- import --apply --expected-database OCR_IsolatedFixture --clients-sql-aware --work-root 'D:\private-ocr-migration' --manifest 'D:\private-ocr-migration\inventory-001.json' --employee-kind Photo --employees 00123
```

`import` defaults to dry-run. Every import/verification invocation is bounded by 10 files, 134217728 bytes and 45 seconds; `--max-files`, `--max-bytes`, `--max-seconds` can lower these values. A single PDF is limited to 64 MiB and a photo to 5 MiB. Inventory hashes one source at a time and validates extension/signature. Approved roots may be local or UNC; reparse points in roots, ancestors, directories and source files are rejected. Use a persistent private work directory outside temporary storage. Inventory protects its work-root permissions and refuses to overwrite an existing manifest. Manifest contents have an integrity checksum; filesystem protection establishes trust, not the checksum alone.

Inventory reads status without grade filtering: only `ResignDate IS NULL AND (StatusWork IS NULL OR StatusWork <> '0')` is current. Codes remain strings, including leading zeros. Before schema/key finalization, qualification versions are reported as pending/ambiguous and cannot activate. Rebuild inventory after finalization and reader rollout. Database references determine ownership; an unknown filename never establishes an employee or a historical version. Missing, conflicting, unsupported, unknown, resigned and ambiguous outcomes are explicit totals. Identical copies for the same employee/kind/key collapse into one import; different bytes never get an automatic winner.

Resume by running the same reviewed manifest and scope. Each file's bytes, exact owner CAS, alias and migration journal commit in one transaction. The SQL journal is authoritative for crash recovery even when the process stopped after commit and before writing its local checkpoint. Journal identity is employee, kind, canonical relative-key hash and content SHA-256; its full source key is also checked. A retry returns the previously committed FileId. Checkpoints contain the manifest checksum and results; an exclusive work-root lock prevents simultaneous runs sharing that state.

The importer stages and rehashes source content before opening its SQL transaction. Publication locks/rechecks the employee first, then the exact owner GUID/concurrency token and legacy reference. A stale manifest cannot replace any SQL-authoritative reference. Resigned employees are skipped before staging publication, and a resignation during staging is rejected transactionally. Previously imported bytes remain retained. Conflicts require a new reviewed reconciliation; do not edit checksummed manifests by hand.

Verification/dry-run performs source reads and database metadata/status reads only, plus private local checkpoint output. It does not insert file bytes, aliases, business rows or SQL journal records. Status/owner race and restart guarantees also require integration tests against the isolated SQL schema; unit tests alone are insufficient evidence for production activation.
